# Правила оформлення рукопису за шаблоном Springer Nature Word Template

> Джерело вимог: `article_tepmlate/Instructions_SpringerNature_Word_Template.pdf`,
> `article_tepmlate/Word Template_Instruction _укр.docx`, `article_tepmlate/Author.dotm`.
>
> Цей документ регламентує **форму** рукопису (розмітку, структуру, оформлення елементів)
> і правила його **майбутнього перекладу англійською**.
> **Зміст** рукопису (7-розділова схема, критичний аналіз літератури, симетрія «задача —
> підрозділ — висновок», стилістичні заборони) регламентується в [RULES.md](RULES.md).
> У разі суперечності: структура змісту — за `RULES.md`, оформлення елементів — за цим документом.

---

## 1. Головний принцип: структурна розмітка замість форматування

Шаблон Springer Nature — не набір «красивих шрифтів», а **система структурованої розмітки**.
Документ конвертується у видавничий XML, з якого генеруються і друкований макет, і
онлайн-версія. Тому:

1. **Жодного ручного форматування**, якщо для елемента є стиль шаблону. Не можна робити
   заголовок «жирним 14 pt» — треба застосувати стиль `heading1`.
2. **Кожен структурний елемент має власний стиль.** Абзац, анотація, підпис рисунка,
   підпис таблиці, список літератури — усе це різні стилі, а не різні відступи.
3. **Ієрархія заголовків не порушується.** `Heading 2` не може стояти без попереднього
   `Heading 1`; рівні не пропускаються. Доступні рівні: Heading 1 – Heading 5.
4. **Помилкове форматування знімається через `Delete Format`**, після чого застосовується
   правильний стиль. Не «підчищати» вручну.

Практичний наслідок для цього проєкту: рукопис **не набирається у Word вручну**, а
збирається зі своїх markdown-джерел скриптом, який застосовує стилі шаблону автоматично
(розділ 4).

## 2. Підготовка Word (лише для ручного доопрацювання)

Шаблон `Author.dotm` містить макроси. Щоб вкладка **Styling** зʼявилася в стрічці:

1. Word → `File` → `Options` → `Trust Center` → `Trust Center Settings` → `Macro Settings`.
2. Обрати **Disable all macros with notification**, `OK` двічі.
3. Закрити Word.
4. Відкрити `Author.dotm` — зʼявиться вкладка **Styling**.

Вкладка поділена на пʼять блоків: `Styling`, `Chapter Header`, `Chapter Body`,
`Chapter Back Matter`, `Extras`.

Стиль застосовується так: для нового тексту — поставити курсор на новий рядок, обрати
елемент, почати набирати; для наявного — виділити фрагмент і клацнути елемент.

## 3. Структура рукопису та відповідність 7-розділовій схемі

| Блок шаблону | Елемент | Наш розділ / файл |
|---|---|---|
| Chapter Header | Chapter Title | назва статті, `00-titul-anotatsiya.md` (розд. 3.2) |
| | Author Name | автори (повні імʼя та прізвище кожного співавтора) |
| | Affiliation | **обовʼязково**: `Department, Institution, City, Country` (розд. 3.2) |
| | Abstract | Резюме / Abstract |
| | Keywords | 5–10 ключових слів |
| | Chapter Number, Chapter Note, Motto | не використовуються (це елементи книжкової глави) |
| Chapter Body | Heading 1–5 | розділи 1–7 та підрозділи |
| | Paragraph | основний текст |
| | List, Equation, Figure, Table, Computer Code | відповідні елементи розділів 4–6 |
| Chapter Back Matter | Competing Interests | «Конфлікт інтересів», `07-vysnovky.md` |
| | Acknowledgments | «Подяка» |
| | Appendix | додатки (за наявності) |
| | Reference List Heading / Entry | `08-literatura.md` — єдиний зведений список |
| | (вимога укр. редакції) | «Відомості про авторів», `09-vidomosti-pro-avtoriv.md` |
| Extras | Table of Contents, Index | **видалити перед поданням** |

### 3.1. Назва статті

Назва береться з **прийнятої редакцією анотації**
(`article_rules/Аннотація_Лісняк_Котов_Чопоров.docx`) і не змінюється самовільно:

- English: **FlexiCubes-Based Polygonization of Geometric Models Defined by R-Functions**
- Українською: **Полігонізація геометричних моделей, заданих R-функціями, методом FlexiCubes**

Будь-яка зміна назви в `article/00-titul-anotatsiya.md` має бути узгоджена з редакцією:
поданий рукопис мусить збігатися за назвою з прийнятою анотацією.

### 3.2. Афіліації

Афіліація — **окремий обовʼязковий елемент** шаблону: щонайменше одна повна й коректна
для кожного співавтора. Формат за інструкцією видавця:

```
Department, Institution, City, Country
```

Афіліація записується окремим абзацом **безпосередньо під рядком авторів** — складальник
розпізнає її за позицією і застосовує стиль `affiliation`:

```markdown
**А. Б. Лісняк, Р. О. Котов, С. В. Чопоров**

Кафедра програмної інженерії, математичний факультет, Запорізький національний університет, Запоріжжя, Україна
```

Усі три автори працюють в одному підрозділі, тому подається **один спільний рядок
афіліації без верхніх індексів**. Якби афіліації різнилися, кожна отримала б свій номер
(`1Department…`, `2Department…`), а імена авторів — відповідні верхні індекси.

У прийнятій анотації афіліації наведено разом із посадами («Head of the Department…»,
«PhD student…», «Supervisory Board Member»). Посада **не є частиною афіліації** за
форматом Springer і в титульну частину не виноситься.

Розгорнуті «Відомості про авторів» (наукові ступені, посади, ORCID, e-mail, поштова
адреса) залишаються в кінці рукопису — це вимога української редакції, а не шаблону
Springer, і вона не замінює афіліацію в титульній частині.

## 4. Автоматичне складання docx

Рукопис збирається командою:

```bash
python tools/build_article.py -p full        # -> build/manuscript.docx
```

Складальник відкриває `Author.dotm`, забирає з нього стилі, нумерацію та параметри
сторінки і розставляє стилі за ролями елементів. Набір стилів `springer` працює в режимі
`create_styles = false` / `manual_formatting = false` — тобто **не створює власних стилів
і не задає шрифтів**, як того вимагає інструкція видавця.

Відповідність «елемент рукопису → стиль шаблону» (див. `article-build.toml`,
секція `[stylesets.springer.styles]`):

| Елемент у markdown | Стиль шаблону |
|---|---|
| назва статті (`#` у преамбулі) | `Main_Title` |
| рядок авторів (жирний абзац під назвою) | `author` |
| афіліація | `affiliation` |
| резюме / abstract | `abstract` |
| ключові слова | `keyword` |
| заголовки розділів `#`…`####` | `unheading1`…`unheading4` |
| абзац | `para` |
| перший абзац після заголовка | `noindentpara` |
| виносна формула `$$…$$` | `equation` |
| рисунок | `noindentpara` (по центру) |
| підпис рисунка | `figure` |
| підпис таблиці | `tablelegend` |
| комірка таблиці | `table` |
| елемент списку | `para` з явним маркером |
| запис списку літератури | `reference` (номер + табуляція + текст) |
| заголовок «Література / References» | `references` |
| програмний код | `computercode` |

Два свідомі відхилення від «чистих» стилів шаблону, обидва керовані прапорцями в
`article-build.toml`:

- `plain_title = true` — стиль `Main_Title` розрахований на **нумеровану главу книги**:
  він додає номер «1» перед назвою і розрив сторінки. Для статті і те, й інше знімається.
- `equation_tab = true` — стиль `equation` центрує формулу по табуляції (позиції 3204/6634
  твіпів), тому перед формулою ставиться символ табуляції.

Ненумеровані заголовки (`unheading*`) обрані тому, що нумерація розділів (1–7, 5.1, 5.2)
є частиною змісту за `RULES.md` і має точно відповідати номерам задач і висновків. Якщо
редакція вимагатиме автоматичної нумерації шаблону — замінити `heading1..4` на
`"heading1".."heading4"` і виставити `strip_heading_numbers = true`.

### 4.1. Допоміжний вихід у LaTeX

```bash
python tools/build_article.py -f tex         # -> build/manuscript.tex
python tools/build_article.py -f both        # docx і tex з того ж markdown
```

**Формат подання до редакції — `.docx` за шаблоном `Author.dotm`.** LaTeX-вихід
допоміжний: PDF для вичитки та обговорення, препринт, заготовка англомовного варіанта
(розд. 6). Офіційного LaTeX-класу Springer Nature у проєкті немає, тому `.tex` не
замінює рукопис для видавця.

Правило, яке з цього випливає: **рукопис не конвертується з одного формату в інший**.
Єдине джерело — markdown у `article/`; `.docx` і `.tex` рендеряться з нього незалежно
(`article_builder/docx_writer.py` і `article_builder/latex_writer.py`). Правити
згенерований `.tex` або `.docx` вручну не можна — правки вносяться в markdown.

Логіка розмітки в LaTeX-виході та сама, що й для Word: роль елемента → макрос преамбули
(`[latex.macros]` замість `[stylesets.springer.styles]`), типографіка — зі спільної
секції `[style]`. Параметри виходу описані в `tools/README.md`, розділ «LaTeX».

## 5. Правила написання markdown-джерел

Щоб складальник коректно розпізнав елементи, у файлах `article/*.md` діють такі правила.

### 5.1. Заголовки

- `#` — розділ (1–7), `##` — підрозділ (5.1), `###` — підпідрозділ. Рівні не пропускати.
- Номер розділу пишеться в тексті заголовка: `## 5.2. Порівняльне дослідження…`.
- Назва статті — `#` без номера у преамбулі; наступний **жирний** абзац автоматично
  розпізнається як рядок авторів, а абзац одразу за ним — як афіліація (розд. 3.2).

### 5.2. Абзаци та заголовки всередині абзацу

Шаблон має три стилі run-in-заголовків. У markdown вони записуються так:

- Style 1 (жирний лід-ін): `**Форма елементів**: далі текст того самого абзацу.`
- Style 2 (жирний курсив): `***Форма елементів***: далі текст.`
- Style 3 (жирний, текст з нового рядка): окремий `####`-заголовок.

### 5.3. Формули

- Рядкова: `$\alpha_{\min}$` — потрапляє в текст як нативна формула Word (OMML).
- Виносна: `$$…$$` на окремому рядку.
- Розділовий знак у кінці виносної формули (`,` `.`) складальник виносить за межі формули.
- Шаблон підтримує нумеровані виносні формули; у поточному тексті нумерації формул немає.
  Якщо вона знадобиться, номер ставиться табуляцією в кінці рядка, а посилання в тексті —
  `Eq. (1)`.

### 5.4. Рисунки

- Розмітка: `![Опис](assets/файл.png)`, наступним рядком — підпис курсивом.
- **Підпис завжди ПІД рисунком.**
- Формат підпису в англомовній версії: `**Fig. 1** ` жирним, далі текст підпису
  звичайним накресленням.
- Посилання в тексті — `→ Fig. 1` (в українській версії — «на рис. 1»).

### 5.5. Таблиці

- **Підпис завжди НАД таблицею**: рядок `*Таблиця N*`, далі жирний рядок назви, далі
  сама таблиця.
- Формат підпису в англомовній версії: `**Table 1** ` жирним, далі текст.
- Переведення рядка всередині комірки — `<br>`.
- Виноски до таблиці (`Table Footnote`) розміщуються безпосередньо під таблицею.
- **Широкі таблиці.** Смуга набору шаблону Springer — лише 11,7 см. Таблиця, що не
  вміщується, автоматично виноситься складальником на власну **альбомну сторінку**
  (`landscape_wide_tables = true`). Якщо в комірці стоїть виносна формула, вона не
  переноситься — такі формули краще виносити з таблиці в текст.

### 5.6. Списки

- Нумерований список — `1.`, `2.`, …; маркований — `-`.
- Номери зберігаються такими, як написані (складальник не перенумеровує), щоб нумерація
  задач, висновків і джерел не «поїхала».
- Підсписок (`Sublist`) у шаблоні позначається тире; у markdown — вкладений рівень.

### 5.7. Цитування та список літератури

- **Стиль цитування — числовий** (`Reference Citation [Number]` / `Reference List Entry
  Numbered`). Рішення ухвалено і діє на весь рукопис, включно з англомовною версією.
  Змішувати з «автор–рік» заборонено — інструкція видавця вимагає одного стилю в межах
  усієї глави.
- У тексті: `[1]`, `[1, 2]`, `[4, 25]` — у квадратних дужках.
- Записи списку літератури — нумерований список у **єдиному файлі**
  `article/08-literatura.md` під заголовком `# Література / References`. Окремих переліків
  джерел у розділах не ведеться: там лишаються тільки посилання `[N]`.
- Заголовок списку літератури складальник розпізнає за словами «Література», «References»,
  «Бібліограф*».

### 5.8. Службові блоки

Робочі матеріали відсікаються за regexp у `drop_sections`. Наразі це реєстр
«Верифікація джерел» у кінці `08-literatura.md` (робота → що підтверджує → розділи →
наявність PDF). Будь-який новий службовий блок треба або назвати так само, або додати
його маркер у `article-build.toml`.

### 5.9. Блоковий код і цитати

- Програмний код — огороджений блок ``` ``` ``` ```; отримує стиль `computercode`.
- Довга цитата — `Block Quote` шаблону; у markdown поки не використовується.

### 5.10. Спеціальні (дидактичні) абзаци

Шаблон має вісім типів: `Example`, `Definition`, `Warning`, `Overview`, `Important`,
`Question`, `Legal`. Кожен **обовʼязково завершується End Tag**; якщо блок із кількох
абзаців — End Tag ставиться вручну після останнього. У науковій статті цього типу вони
зазвичай не потрібні; складальник їх не генерує.

## 6. Правила майбутнього перекладу англійською

### 6.1. Організація файлів

Переклад ведеться **дзеркально**, файл у файл, щоб зберегти відповідність
«задача — підрозділ — висновок»:

```
article/
  00-titul-anotatsiya.md      article/en/00-title-abstract.md
  01-vstup.md                 article/en/01-introduction.md
  ...                         ...
```

Профіль складання додається в `article-build.toml`:

```toml
[profiles.full-en]
description = "English manuscript (Springer template)"
output = "manuscript-en.docx"
styleset = "springer"
sections = ["en/00-title-abstract.md", "en/01-introduction.md", "..."]

[profiles.full-en.style]
lang = "en-GB"
bullet_marker = "–"
```

Рисунки **не дублюються**: шляхи `assets/…` спільні. Підписи до них перекладаються.

### 6.2. Назви розділів

7-розділова схема зберігається; англомовні відповідники:

| Укр. | English |
|---|---|
| 1. Вступ | 1. Introduction |
| 2. Аналіз літературних даних та постановка проблеми | 2. Literature Review and Problem Statement |
| 3. Мета та задачі дослідження | 3. The Aim and Objectives of the Study |
| 4. Матеріали та методи досліджень | 4. Materials and Methods |
| 5. Результати досліджень | 5. Results |
| 6. Обговорення результатів | 6. Discussion |
| 7. Висновки | 7. Conclusions |
| Конфлікт інтересів | Competing Interests |
| Фінансування | Funding |
| Подяка | Acknowledgments |
| Внесок авторів | Author Contributions |
| Література / References | References |

| роздільна здатність ґратки | grid resolution |

| центроїдний колапс | centroid collapse |
| коефіцієнт форми елемента | element shape factor |

**Не перекладаються:** назви алгоритмів (Marching Cubes, Dual Contouring, Dual Marching
Cubes, FlexiCubes), назви програмних бібліотек, ідентифікатори у формулах
($E_{\mathrm{surf}}$, $\alpha_{\min}$, $S_{<10^\circ}$).

### 6.4. Типографіка англомовної версії

- Десятковий роздільник — **крапка** (`0.123`), як і в українській версії.
- Діапазони — коротке тире без пробілів: `14.03°–15.66°`, `2021–2025`.
- Лапки — `“…”` (у українській версії — `«…»`).
- Нерозривний пробіл між числом і одиницею: `0.168 s`, `32³ grid`.
- Відсоток: `4.08 %` (з пробілом) — послідовно в усьому тексті.
- «Рис.» → `Fig.`, «Табл.» → `Table`, «розд.» → `Sect.`, формула → `Eq. (1)`.
- Перехресні посилання в шаблоні Springer оформлюються як `→ Fig. 1`, `→ Table 1`,
  `→ Sect. 2`.

### 6.5. Стиль наукового викладу

- Зберігається **безособовий пасивний стан** (`It was established that…`,
  `The results show…`); заборона «ми-парадигми» з `RULES.md` діє й в англомовній версії.
- Час: результати — Past Simple (`was determined`), загальні твердження та висновки —
  Present Simple (`DMC guarantees…`).
- Abstract будується за тією самою схемою: обʼєкт → проблема → суть результатів →
  завдяки чому → чим пояснюються → умови застосування.
- Abstract і Keywords у шаблоні мають run-in-заголовки: слова `Abstract` і `Keywords`
  додаються стилем автоматично — **не дублювати їх у тексті**.
- Кількість ключових слів — 5–10 (в українській версії їх 10; за потреби скоротити).

### 6.6. Список літератури в англомовній версії

**Стиль — числовий** (`Reference List Entry Numbered`), той самий, що й в українській
версії. Нумерація джерел і посилання `[N]` у тексті **зберігаються без змін**, тому
переклад не порушує відповідності «посилання ↔ джерело»: перекладаються лише ті частини
записів, що подані українською або російською.

Записи оформлюються так: номер, табуляція, сам запис (складальник ставить табуляцію
автоматично — `reference_tab = true`).

Приклади Name–Year з інструкції видавця (Slifka & Whitton 2000 тощо) у цьому рукописі
**не застосовуються** — вони наведені в PDF лише як зразок альтернативного стилю.

Кириличні джерела (Рвачов) подаються транслітеровано з англійським перекладом назви у
дужках, як у прикладі інструкції:

```
Marikhin VY, Myasnikova LP (1977) Nadmolekulyarnaya struktura polimerov
  (The supramolecular structure of polymers). Khimiya, Leningrad
```
