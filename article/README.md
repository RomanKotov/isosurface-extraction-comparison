# Структура рукопису статті (IMRaD) та регламент складання

Текстовий масив рукопису організовано за міжнародним академічним стандартом **IMRaD** (Introduction, Materials and Methods, Results, and Discussion) у директорії `article/`. Усі матеріали розбито на 6 пронумерованих послідовних файлів, узгоджених із первинними джерелами з директорії `articles_pdf/`.

Єдиний вихідний документ `.docx` збирається скриптом `tools/build_article.py` за офіційним видавничим шаблоном Springer Nature (`article_tepmlate/Author.dotm`). **У Word рукопис не набирається і згенерований `.docx` руками не правиться** — усі зміни вносяться виключно в markdown-файли, після чого документ перескладається (`RULES-SPRINGER.md`, розд. 1 і 4).

## Структура документів

| Файл | Розділ за схемою IMRaD | Зміст документа |
|---|---|---|
| **`01-abstract.md`** | **Abstract & Front Matter** | УДК 004.92:519.6, результат-орієнтована назва (укр. + англ.), автори, афіліації, структуровані 6-компонентні анотації (по 1800+ знаків), 10 ключових слів |
| **`02-introduction.md`** | **1. Introduction** | Актуальність (САПР/МСЕ, NASA Vision 2030), SDF проти R-функцій Рвачова, вимоги до сіток МСЕ, критичний огляд 3 класів методів (MC, DC, DMC, FlexiCubes), загальна невирішена проблема, мета і 3 конкретні задачі |
| **`03-materials-and-methods.md`** | **2. Materials and Methods** | Об'єкт, гіпотеза, комплексна 4-рівнева система критеріїв якості сітки для МСЕ, аналітичні системи R-функцій ($R_0, R_\alpha, R_p, R_{m0}, \min/\max$), теоретико-множинне об'єднання куба та циліндра (Рис. 1), алгоритми екстракції, конвеєри постобробки |
| **`04-results.md`** | **3. | **`05-discussion.md`** | **4. Discussion** | Геометрична інтерпретація результатів (стабільність DMC, деградація DC на полях високого порядку), зіставлення з літературою, практичні рекомендації, обмеження, 3 симетричні висновки (Conclusions), декларації (CRediT), відомості про авторів |
| **`06-references.md`** | **References** | Єдиний нумерований список 29 рецензованих першоджерел з активними DOI + службовий реєстр верифікації тверджень за фізичними PDF-файлами |

| `assets/` | *Ілюстрації* | Графіки, діаграми та рендери сіток (`.png`), на які посилається текст |

## Підготовка оточення (один раз)

```bash
poetry install --with article                  # або: pip install python-docx latex2mathml lxml
```

Формули переносяться в Word як нативні об'єкти (OMML) через таблицю стилів `MML2OMML.XSL` з комплекту MS Office — вона знаходиться автоматично. Якщо Office встановлено в нестандартному каталозі, шлях задається в `article-build.toml` (`build.math_xsl`) або змінною оточення `MML2OMML_XSL`.

## Основні команди збирання

Запускати з кореня репозиторію:

```bash
python tools/build_article.py                  # повний рукопис -> build/manuscript.docx
python tools/build_article.py --list           # перелік профілів і наборів стилів
python tools/build_article.py -p blind         # анонімізований варіант для сліпого рецензування
python tools/build_article.py -p abstract      # лише титул, резюме та ключові слова
python tools/build_article.py -p proofread     # без рисунків, полуторний інтервал для вичитки
python tools/build_article.py -p results       # матеріали + результати + обговорення
```

| Профіль | Файл | Призначення |
|---|---|---|
| `full` | `manuscript.docx` | повний рукопис за схемою IMRaD (усі 6 документів) |
| `blind` | `manuscript-blind.docx` | сліпе рецензування (без титулу та відомостей про авторів: розділи 02–06) |
| `abstract` | `abstract.docx` | окремий файл метаданих та анотацій на вимогу редакції (`01-abstract.md`) |
| `proofread` | `manuscript-proofread.docx` | текстовий варіант для вичитки (без рисунків) |
| `results` | `results.docx` | експериментально-аналітична частина (`03-`, `04-`, `05-`) |

## Додаткові прапорці та параметри

```bash
python tools/build_article.py -s 04-results.md -o build/rezultaty.docx     # скласти один розділ
python tools/build_article.py -s 0[3-5]-*.md -o build/core.docx            # діапазон розділів
python tools/build_article.py -p full --no-figures                         # без рисунків
python tools/build_article.py -p full --no-tables                          # без таблиць
python tools/build_article.py -f tex                                       # вихід у LaTeX (manuscript.tex)
python tools/build_article.py -f both                                      # одночасно docx і tex
```

## Що автоматично відсікається від публікації

Службові блоки видаляються автоматично за правилом `drop_sections` з `article-build.toml`:
- `^Верифікація джерел` (службова таблиця в кінці `06-references.md` з відповідністю тверджень та наявністю PDF);
- `^Джерела розділу` (внутрішні робочі примітки);
- У профілі `blind` додатково відсікаються блоки «Подяка», «Внесок авторів» та «Відомості про авторів».
