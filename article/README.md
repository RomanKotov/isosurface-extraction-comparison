# Складання рукопису в docx

Розділи рукопису лежать у цій директорії окремими markdown-файлами; єдиний `.docx`
збирається скриптом `tools/build_article.py` за шаблоном видавця. **У Word рукопис не
набирається і згенерований `.docx` руками не правиться** — усі зміни вносяться в
markdown і документ перескладається (`RULES-SPRINGER.md`, розд. 1 і 4).

| Файл | Розділ |
|---|---|
| `00-titul-anotatsiya.md` | УДК, назва, автори, афіліації, резюме, ключові слова (укр. + англ.) |
| `01-vstup.md` | 1. Вступ |
| `02-ohlyad.md` | 2. Аналіз літературних даних та постановка проблеми |
| `03-meta-zadachi.md` | 3. Мета та задачі дослідження |
| `04-materialy-metody.md` | 4. Матеріали та методи досліджень |
| `05-rezultaty.md` | 5. Результати досліджень |
| `06-obgovorennya.md` | 6. Обговорення результатів |
| `07-vysnovky.md` | 7. Висновки |
| `08-literatura.md` | Література / References (єдиний зведений список) |
| `09-vidomosti-pro-avtoriv.md` | Відомості про авторів |
| `assets/` | рисунки, на які посилається `![…](assets/…)` |

## Підготовка (один раз)

```bash
poetry install --with article                  # або: pip install python-docx latex2mathml lxml
```

Формули переносяться в Word як нативні об'єкти (OMML) через таблицю стилів
`MML2OMML.XSL` з комплекту MS Office — вона знаходиться автоматично. Якщо Office
встановлено нестандартно, шлях задається в `article-build.toml` (`build.math_xsl`) або
змінною оточення `MML2OMML_XSL`; інакше формули вставляться простим текстом, і звіт
складання це напише.

## Основні команди

Запускати з кореня репозиторію:

```bash
python tools/build_article.py                  # повний рукопис -> build/manuscript.docx
python tools/build_article.py --list           # перелік профілів і наборів стилів
python tools/build_article.py -p blind         # анонімізований варіант для рецензування
python tools/build_article.py -p abstract      # лише титул, резюме та ключові слова
python tools/build_article.py -p proofread     # без рисунків, полуторний інтервал
python tools/build_article.py -p draft         # кожен розділ з нової сторінки
python tools/build_article.py -p results       # методи + результати + обговорення
```

Усе лягає в `build/`; директорія перезаписується при кожному складанні.

| Профіль | Файл | Для чого |
|---|---|---|
| `full` | `manuscript.docx` | подання до редакції |
| `blind` | `manuscript-blind.docx` | сліпе рецензування (без титулу й відомостей про авторів) |
| `abstract` | `abstract.docx` | окремий файл анотацій на вимогу редакції |
| `proofread` | `manuscript-proofread.docx` | вичитка тексту |
| `draft` | `manuscript-draft.docx` | друк робочої версії |
| `results` | `results.docx` | внутрішнє обговорення експериментальної частини |

## Разові варіанти складання

```bash
python tools/build_article.py -s 05-rezultaty.md -o build/rezultaty.docx   # один розділ
python tools/build_article.py -s 0[4-6]-*.md -o build/core.docx            # діапазон розділів
python tools/build_article.py -p full --no-figures                         # без рисунків
python tools/build_article.py -p full --no-tables                          # без таблиць
python tools/build_article.py --styleset journal                           # шаблон редакції
python tools/build_article.py -t path/to/other.dotm                        # інший шаблон
python tools/build_article.py -p full -q                                   # без звіту
```

## Звіт складання

Після кожного запуску скрипт друкує, які розділи увійшли, який шаблон використано, звідки
взято таблицю стилів для формул і які попередження виникли. На попередження треба
реагувати — типові:

- `не знайдено зображення: assets/…` — рисунок відсутній, у документі лишиться позначка;
- `стиль "…" (роль …) відсутній у шаблоні` — шаблон не той або роль названо неправильно;
- `таблиця «…» не вміщується навіть за 8 pt` — скоротити заголовки стовпців.

## Що не потрапляє в документ

Службові блоки видаляються автоматично за `drop_sections` з `article-build.toml`: збіг
прибирає заголовок і все далі до наступного заголовка того ж або вищого рівня. Зараз
шаблони — `^Верифікація джерел` (реєстр у кінці `08-literatura.md`) і `^Джерела розділу`
(робочі таблиці, якщо знову з'являться в розділах). Профіль `blind` додатково прибирає
«Подяка», «Внесок авторів» і «Відомості про авторів».

`manuscript_full.md` — зведена чернетка всього тексту одним файлом; у профілі вона не
входить і в складання не потрапляє. Джерело правди — окремі файли розділів.
